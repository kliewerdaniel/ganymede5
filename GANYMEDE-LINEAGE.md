# Ganymede Lineage

Four generations. One recurring question: **can a system that reasons be trusted to
report on its own reasoning?** Each generation moved the question up a level.

This document is a map, not a history. Milestone documents inside each repository remain
the authoritative record of what happened there, including what failed.

---

## The arc

| | Ganymede | Ganymede2 | Ganymede4 | Ganymede5 |
|---|---|---|---|---|
| **Core object** | Document | Claim | Versioned artifact | Normative commitment |
| **Question** | Can it cite? | Can it compile knowledge deterministically? | Can it be governed at runtime? | Can it be *measured* without self-deception? |
| **LLM role** | Assistant | Optional refinement, late | One probabilistic component under a gate | **None. Absent entirely.** |
| **Key mechanism** | Provenance | Epistemic/Evidence graph split | Witness + policy gateway + auditor | Specification freeze + independent implementations |
| **Failure found** | Untraceable claims | Corpus as mutable | Self-attesting evidence (97%) | Measurement reporting success while dropping 5 of 41 cases |
| **Evidence form** | Human review | Deterministic artifacts | 689 tests, 32 ADRs | 78 tests, 19 mutants, 7 detectors |

## Per-mechanism lineage

### Corpus
Ganymede: files. Ganymede2: **immutable infrastructure** — content hash, source ID,
parser version, origin metadata; raw recoverable, derived regenerable. Ganymede4:
compiled artifact, corpus deliberately *not committed*. Ganymede5: corpus becomes
**neutral ground** — a label-free file no implementation writes, from which the harness
derives its own expected population.
*Inherited:* corpora are versioned infrastructure, never generated by the thing they
judge. *New risk introduced at each step:* a corpus the system can write is a corpus the
system can flatter itself with.

### Evidence and claims
Ganymede2 established the split that everything downstream inherits: **Evidence Graph**
(what exists, immutable) vs **Epistemic Graph** (what is inferred, revisable). Ganymede4
made claims *propositions* (ADR-012) and made "a duplicate is not a witness" (ADR-019).
Ganymede5's contribution is different in kind: it does not reason about evidence, it
reasons about **whether its own reasoning was observed**.
*Failure:* 97% of claims marked SUPPORTED were attested only by copies of themselves.

### Epistemic state
Ganymede2: 8-state machine, never boolean, status a pure function of evidence. Ganymede4:
ADR-002 fixes the vocabulary; ADR-017 and ADR-021 govern revision and resealing.
Ganymede5 adds a state **orthogonal to all of them**: `VACUOUS` — satisfied without
being exercised. This is the lineage's sharpest single idea.
*Inherited:* status is never a boolean; absence of evidence is not a status.

### Uncertainty and negative knowledge
Ganymede2 principle 7: "no evidence found" ≠ "evidence insufficient" ≠ "sources
contradict" ≠ "support withdrawn". Ganymede5 §2.1 makes it mechanical: a defective
corpus is `INVALID/CORPUS`, **never** `NONE`, because `NONE` asserts both that the
semantics decided and that the corpus is fine.

### Compilation and determinism
The strongest through-line, and the reason Ganymede5 has **no LLM in it at all**:

```
expensive intelligence → compile → deterministic artifact → cheap inspection
```

Ganymede2 called it the epistemic compiler. Ganymede4 made it a one-command build that
exits non-zero on a failed audit. Ganymede5 pushed it furthest — proving the
*specification itself* compiles deterministically, by requiring four independent
implementations to produce identical output from prose alone.

### Authority and policy
Ganymede4 is where this lives: witness, independent auditor, fail-closed policy gateway,
separation of authorities (ADR-005, 006, 007, 008, 014, 028, 029). ADR-029 — *"the model
is not an input to the write"* — is the operative rule. Ganymede5 makes no governance
claim and preserves the question as unasked.
*Not yet inherited into an implemented system:* Ganymede5 has no policy layer at all,
deliberately.

### Verification and measurement
This is Ganymede5's entire subject, and the lineage's most important arc. Ganymede4
verified *artifacts* (recompute the Merkle root, never print a stored digest). Ganymede5
asks the prior question: **who verifies the verifier?** Its answer is the coverage
invariant — the harness refuses to report agreement over any case set that is not
identical across corpus, implementation A, implementation B, and the compared set.
*The failure it exists to catch:* the harness compared 36 of 41 cases and printed
VERDICT. Not a red. Green.

### Merkle and content addressing
Ganymede4: ADR-018 (artifact version must cover state), ADR-021 (reseal after bulk
change), ADR-022 (bulk writes must re-establish invariants). The recurring lesson is that
an identity function that cannot *see* a change will not notice it. **Not inherited by
Ganymede5**, which has no artifact-identity requirement.

### Governance
Ganymede4 built a runtime gate. Ganymede5 declined to extend it, on the grounds that a
governance question needs an independently specified corpus to be worth asking. The
question is preserved verbatim and **unimplemented** — the correct disposition, and the
one most likely to be quietly converted into a backlog item by a later generation.

## What each generation learned that it could not have known before

**Ganymede** learned that a citation is not provenance.

**Ganymede2** learned that evidence and interpretation have different mutability, and
that conflating them makes a belief unrevisable without destroying its basis.

**Ganymede4** learned — by running things, three separate times — that a documented
pipeline component which was never executed looks exactly like a working one. Belief
revision, next-version, and evidence verification were each decorative when first
written. Each was found by running the system, and each had looked like success.

**Ganymede5** learned that the measuring instrument is the most dangerous component in
the system, because its failures are *green*. Every other failure category produces
visible red. And it learned — at closure, in this audit — that **its own README had
drifted from its own experiment**: it claimed four implementations at 0 disagreements when
one of them, run against the current corpus, disagreed on six cases. The drift was in
documentation, not semantics, which is precisely the category a reader is least able to
audit and most likely to trust.

## The failure ledger (preserved deliberately)

These are not debris. They are the empirical content of the lineage.

- Corpus as mutable infrastructure (Ganymede2's founding constraint)
- Self-attesting evidence: 97% of SUPPORTED claims (G4, ADR-019)
- Belief revision not existing for eleven phases (ADR-017)
- Merkle root blind to epistemic-state change (ADR-018)
- The root cannot see text (ADR-026)
- Bulk writes not re-establishing invariants (ADR-022)
- A container mistaken for a second witness (ADR-024)
- Harness comparing 36 of 41 cases and reporting success (G5)
- A stale result file indistinguishable from a current one (G5)
- An adversarial test aimed at the wrong failure model (G5 — the detector targeted B, the bug was in A)
- §6.3 satisfied vacuously by an implementation with no budget (G5)
- `DEFEATED` advertised but unreachable (G5)
- Specification edited to accommodate a measurement (G5, v0.2 — recorded as a decision, which is the point)
- **A README claiming a result its own repository contradicted (G5, found at closure)**

## The common abstraction

Derived from the four repositories rather than assumed:

```
SOURCE → EVIDENCE → CLAIM → EPISTEMIC STATE → REASONING → PROPOSAL
       → AUTHORITY → ACTION → OBSERVATION → VERIFICATION → REVISION → NEW VERSION
```

with one addition the lineage forced and no earlier generation anticipated:

```
        …and a MEASUREMENT BOUNDARY observing every arrow above,
        which is forbidden from writing to any of them.
```

That last boundary is Ganymede5's whole contribution, and it is the layer Ganymede6 must
generalise rather than re-invent per experiment.

**The invariant all four generations independently re-derived:** the component that
produces a conclusion must never be the component that validates it.
